# Etapa 1.5: Cloud Run

## Objetivo

Publicar la imagen de la API en Artifact Registry y ejecutarla en Cloud Run con una cuenta de servicio de permisos mínimos, sin acceso público.

**Terminado cuando:** la API responde en Cloud Run.

**Estado:** terminada (verificada en GCP el 2026-11-24). Cambio respecto del plan: el servicio se creó con Terraform (`google_cloud_run_v2_service`), no con `gcloud run deploy`, y nunca tuvo acceso público (las pruebas usan un token de identidad).

## Pasos hechos

1. Repositorio Docker `quotes` en Artifact Registry (`us-central1`).
2. Cuenta de servicio `quotes-runtime`, con solo dos permisos: `roles/cloudsql.client` en el proyecto (Cloud SQL no tiene IAM por instancia) y `roles/secretmanager.secretAccessor` sobre su secreto `quotes-db-password`.
3. Imagen construida en local, etiquetada con el commit (`api:f08db3b`) y subida con `docker push`. Sin Cloud Build. El build usó la caché, porque `uv.lock` no cambió, y no descargó dependencias.
4. Servicio `quotes-api`:
   - Privado: no hay binding `allUsers`, así que sin token responde 403.
   - Escalado de 0 a 2 instancias, con 1 CPU y 512 MiB, y CPU solo durante las solicitudes (`cpu_idle`).
   - Conexión integrada a Cloud SQL: un volumen que monta el socket en `/cloudsql/<instancia>`.
   - `DB_PASSWORD` llega como variable desde Secret Manager; `DB_USER`, `DB_NAME` e `INSTANCE_CONNECTION_NAME` llegan como variables normales.
5. `app/config.py` arma la URL de la base con esas partes cuando no hay `DATABASE_URL`. El modo local no cambia.

## Comandos usados

| Comando | Para qué |
|---|---|
| `gcloud auth configure-docker us-central1-docker.pkg.dev` | Que Docker use las credenciales de gcloud para ese registro (modifica `%USERPROFILE%\.docker\config.json`). |
| `docker build -t <registro>/api:<commit> .` | Construir la imagen con la etiqueta del registro. |
| `docker push <registro>/api:<commit>` | Subir la imagen a Artifact Registry. |
| `gcloud auth print-identity-token` | Obtener un token de identidad del usuario para llamar al servicio privado. |
| `curl.exe -H "Authorization: Bearer <token>" <url>/health` | Llamar al servicio privado con el token. |

## Resultado observado

- Sin token: `HTTP 403`.
- Con token: `/health` responde `{"status":"ok"}`; `POST /quotes` devuelve un id; `GET /quotes/{id}` devuelve la misma cotización; un id inexistente da 404 con el formato de error único.

## Costo y limpieza

Cloud Run con mínimo 0 instancias no cobra si no recibe solicitudes. Cada imagen ocupa unos 150 MB en Artifact Registry (el repositorio mide 148 MB); se borran con el repositorio en el retiro. Ver [docs/costos-y-retiro.md](../costos-y-retiro.md).
