# Etapa 0.2: Entorno local y repo

## Objetivo

Dejar listo el entorno de desarrollo local y el repositorio (pasos 4 a 8 de la sección 8 del plan): herramientas instaladas una sola vez, `gcloud` apuntando al proyecto del laboratorio, proyecto Python con `uv` y estructura `app/` plana, y pre-commit con gitleaks, ruff y mypy.

**Terminado cuando:** pre-commit bloquea un secreto de prueba y `gcloud` apunta al proyecto correcto.

## Pasos hechos

1. Herramientas instaladas con winget (uv, Terraform, gh, Google Cloud SDK) más Docker Desktop y Git for Windows; verificadas en una terminal nueva.
2. `gcloud` autenticado (usuario y ADC) y con el proyecto `python-gcp-ai-lab` configurado.
3. `uv init` ajustado a `app/` plano: se quitaron `[build-system]` y `[project.scripts]`, se borró `src/` y se agregó `pythonpath = ["."]` para pytest.
4. `.gitignore` (cachés, `.env`, Terraform, credenciales, `privado/`), `.gitattributes` con LF, `.env.example` y `.env` local.
5. Dependencias de desarrollo: pytest, ruff, mypy y pre-commit con `uv add --dev`; prueba mínima `tests/test_smoke.py`.
6. `.pre-commit-config.yaml`: gitleaks v8.30.1 (hook oficial) y ruff y mypy como hooks locales con `uv run`.
7. Rama `develop` creada desde `7bbac8c` (commit base de `main`); repo remoto en GitHub.
8. Carpeta `privado/` ignorada para el plan local; `CLAUDE.md` actualizado.

## Comandos usados

| Comando | Para qué |
|---|---|
| `git switch -c develop` | Crear la rama de trabajo diario y cambiarse a ella. |
| `uv add --dev pytest ruff mypy pre-commit` | Agregar herramientas de desarrollo; versiones fijadas en `uv.lock`. |
| `uv run pytest` / `uv run ruff check .` / `uv run mypy app` | Pruebas, lint y tipos con el entorno del proyecto. |
| `git check-ignore -v <ruta>` | Confirmar qué regla de `.gitignore` ignora una ruta. |
| `git add --renormalize .` | Reaplicar `.gitattributes` a los archivos rastreados. |
| `git ls-files --eol` | Ver el final de línea de cada archivo en el índice y en disco. |
| `uv run pre-commit validate-config .pre-commit-config.yaml` | Validar la configuración sin correr hooks. |
| `uv run pre-commit install` | Instalar el hook en `.git/hooks/pre-commit`. |
| `uv run pre-commit run --all-files` | Correr todos los hooks sobre todo el repo. |
| `gcloud config get-value project` | Ver el proyecto activo de `gcloud`. |

## Problemas y solución

| Problema | Solución |
|---|---|
| PATH desactualizado: las terminales abiertas antes de instalar no encontraban las herramientas nuevas. | Abrir una terminal nueva y verificar con `where.exe` y `--version`. |
| `uv` duplicado: un uv 0.11.18 instalado con pip dentro de Python 3.12 (`C:\Users\Ingra\AppData\Local\Programs\Python\Python312\Scripts\uv.exe`) se ejecutaba antes que el de winget. Detectado con `where.exe uv`. | Quitarlo con `python.exe -m pip uninstall uv` usando ese mismo Python, desinstalar todo lo de winget y reinstalar desde una terminal nueva. Resultado: un solo uv 0.13.7, en `%LOCALAPPDATA%\Microsoft\WinGet\Links`. |
| Google Cloud SDK: winget mostró "El instalador solicitará que se ejecute como administrador. Espere una indicación." y terminó en "Instalación abandonada" porque no se aceptó el aviso de UAC. Quedó un registro huérfano: winget lo daba por instalado con versión "Unknown", pero `gcloud` no existía. | `winget uninstall`, reinstalar aceptando el aviso de administrador y verificar en una terminal nueva. Quedó en `C:\Program Files (x86)\Google\Cloud SDK`, versión 592.0.0. |
| LF/CRLF: Git for Windows trae `core.autocrlf=true` y convertía a CRLF al descargar. | `.gitattributes` con `* text=auto eol=lf`, que tiene prioridad sobre `autocrlf`; `git add --renormalize .` no cambió nada porque el índice ya estaba en LF. |
| TLS en el entorno de Claude (no en la máquina del usuario): `uv` daba `UnknownIssuer`, `git fetch` fallaba con `SSL certificate problem` y la instalación de Go se cortaba con `OPENSSL_Applink`. | `--system-certs` solo en los comandos `uv` que ejecuta Claude, nunca en la configuración del proyecto. Los hooks se instalaron desde la terminal del usuario. |
| gitleaks no se pudo instalar desde el entorno de Claude. | Compilado desde la terminal del usuario: pre-commit instaló Go y compiló gitleaks en `~/.cache/pre-commit`, que después reutilizan todos los commits. |

**Lección:** ante "comando no reconocido", primero `where.exe` en una terminal nueva; no reinstalar a ciegas.

## Las 3 preguntas

*Redactadas con IA a partir de las decisiones del chat; revisadas por Ramiro.*

**1. ¿Por qué esta opción y no otra?**

- uv y no pip: una sola herramienta gestiona la versión de Python, el entorno virtual
  y las dependencias, y uv.lock fija versiones exactas para local, CI y Docker. pip
  solo instala paquetes en un Python existente. Las herramientas que no son de Python
  (Terraform, gh, gcloud) se instalan con winget.
- app/ plano y no src/: es un servicio que se despliega como imagen, no una librería.
- pre-commit con gitleaks: frena un secreto antes de que entre al historial. Es más
  barato que rotar una credencial filtrada. Probado con un token falso.
- ruff y mypy como hooks locales con uv run: su versión vive solo en uv.lock.
- .gitattributes con LF: evita que los scripts fallen por CRLF en Linux, Docker y CI.
- Sin claves JSON: ADC guarda las credenciales fuera del repo.

**2. ¿Cómo falla?**

- Si un hook no se puede instalar (red, TLS), ningún commit pasa: falla cerrado, a
  propósito.
- Los hooks se pueden saltar (--no-verify, o clonar sin ejecutar pre-commit install).
  Por eso CI vuelve a correr gitleaks, ruff y mypy (etapa 4.2).
- gitleaks detecta patrones conocidos; una contraseña sin formato reconocible puede
  pasar. Por eso también .gitignore para .env y la regla de no usar claves JSON.
- Si un secreto llega a GitHub, borrarlo del repo no basta: hay que rotarlo.
- En Windows: PATH viejo y herramientas duplicadas; se diagnostica con where.exe en
  una terminal nueva.

**3. ¿Cuánto cuesta y cómo se borra?**

- GCP: US$0, no se creó ningún recurso.
- Local: disco (caché de uv, caché de pre-commit con Go y gitleaks, .venv).
- Borrado: uv run pre-commit clean; uv cache clean; borrar .venv (se recrea con
  uv sync); gcloud auth revoke y gcloud auth application-default revoke; winget
  uninstall.
- Inventario: sin recursos en GCP.
