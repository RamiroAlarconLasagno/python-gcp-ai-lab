# Etapa 1.3: Docker

## Objetivo

Empaquetar la API en una imagen Docker multi-etapa con `uv`: usuario no root, `.dockerignore`, puerto configurable.

**Terminado cuando:** `/health` y `/quotes` responden dentro del contenedor.

**Estado:** bloqueada. El Dockerfile está escrito, pero la imagen todavía no se pudo construir (ver Problemas).

## Pasos hechos

1. `Dockerfile` multi-etapa, siguiendo el patrón de la guía de Docker de uv (verificado en `docs.astral.sh/uv/guides/integration/docker/` y `astral-sh/uv-docker-example`):
   - **Builder:** `python:3.13-slim` con el binario de uv copiado desde `ghcr.io/astral-sh/uv:0.13.7`. Variables `UV_COMPILE_BYTECODE=1`, `UV_LINK_MODE=copy` y `UV_PYTHON_DOWNLOADS=0`. `uv sync --locked --no-dev` en dos capas: primero las dependencias, con montaje de caché, y después el código.
   - **Imagen final:** `python:3.13-slim`, la misma base, porque la ruta del Python del entorno virtual tiene que coincidir. No incluye uv ni herramientas de desarrollo.
   - **Usuario no root** `app` (uid 999).
   - **Arranque:** `CMD` en forma de shell para expandir `${PORT}` (por defecto 8080, como espera Cloud Run); `exec` deja a uvicorn como PID 1.
2. `.dockerignore`: excluye `.git`, `.venv`, `.env`, `privado/`, `tests/`, `docs/`, las cachés y el estado de Terraform.

## Comandos usados

| Comando | Para qué |
|---|---|
| `docker build -t python-gcp-ai-lab:dev .` | Construir la imagen con el Dockerfile del directorio actual. |

## Resultado observado

`docker build` falla en `uv sync --locked --no-install-project --no-dev`:

```
error: Failed to download `typing-inspection==0.4.5`
  cause: invalid peer certificate: UnknownIssuer
```

## Evidencia

- Las imágenes base (`python:3.13-slim`, `ghcr.io/astral-sh/uv:0.13.7`) se descargaron bien: el build llegó al paso 4 de 6.
- Tamaño de la imagen: no disponible, porque la imagen no se construyó.

## Problemas y solución

| Problema | Solución |
|---|---|
| El antivirus **Avast** intercepta el HTTPS de la máquina con su propio certificado (`C:\ProgramData\Avast Software\Avast\wscert.pem`). Windows confía en él, por eso Docker descarga las imágenes base, pero el contenedor del build no, así que la descarga de paquetes de PyPI falla con `UnknownIssuer`. Pasa en cualquier terminal, porque el build corre dentro de Docker. | Pendiente, requiere una decisión. Opciones: (a) excluir `pypi.org` y `files.pythonhosted.org` del escaneo HTTPS de Avast, o desactivar ese escaneo mientras se construye; (b) pasar el certificado de Avast al build como secreto opcional de BuildKit, que agrega complejidad al Dockerfile solo por esta máquina. |
| El puerto 8080 del host está ocupado por otro proceso. | En compose la API se publica en el puerto 8000 del host; dentro del contenedor sigue en 8080. |
