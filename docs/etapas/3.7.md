# Etapa 3.7: ventana de Cloud SQL

## Objetivo

Ejecutar la misma lógica contra Cloud SQL: crear la instancia más chica con pgvector, aplicar las migraciones desde Cloud Run y comprobar que las cotizaciones se guardan y se leen.

**Terminado cuando:** la misma lógica funciona contra PostgreSQL local y Cloud SQL, y no queda ninguna instancia.

**Estado:** desplegada y verificada (2026-11-24). Falta la segunda mitad del "terminado cuando": la instancia vive hasta el 30 de noviembre y se retira en el B6. En este bloque todavía no hay `/ask`: llega con la IA.

## Pasos hechos

1. Instancia `quotes-cdc0b8`, aprobada por Ramiro con su costo estimado:
   - PostgreSQL 17, edición Enterprise, `db-f1-micro` (núcleo compartido), zonal.
   - 10 GB de SSD sin crecimiento automático.
   - Sin backups automáticos y sin protección contra borrado.
   - IP pública sin redes autorizadas: solo entra el conector de Cloud SQL, que valida IAM. Conexiones cifradas obligatorias (`ssl_mode = "ENCRYPTED_ONLY"`).
   - Sufijo aleatorio (`random_id`), porque el nombre de una instancia borrada no se puede reutilizar enseguida.
2. Base `quotes` y usuario `quotes`. La contraseña se genera con `random_password` y se guarda en Secret Manager.
3. Job `quotes-migrate`: misma imagen, misma identidad y misma conexión que el servicio, con `alembic upgrade head` como comando.
4. pgvector: la migración `0001` ejecutó `CREATE EXTENSION IF NOT EXISTS vector` sin error, así que Cloud SQL para PostgreSQL 17 la admite.

## Comandos usados

| Comando | Para qué |
|---|---|
| `terraform -chdir=infra plan -var "image=..." -out=full.tfplan` y `terraform apply full.tfplan` | Crear Cloud SQL, el secreto, el IAM, el servicio y el job. |
| `gcloud run jobs execute quotes-migrate --region us-central1 --wait` | Ejecutar el job de migraciones y esperar a que termine. |
| `gcloud logging read 'resource.type="cloud_run_job" AND resource.labels.job_name="quotes-migrate"' --freshness 10m` | Leer los logs del job. |

## Resultado observado

```
gcloud run jobs execute quotes-migrate --wait  →  Container called exit(0).
logs: Running upgrade  -> 0001, Crea la extensión vector (para el RAG) y la tabla quotes.
```

Después, `POST /quotes` y `GET /quotes/{id}` contra Cloud Run devuelven la misma cotización: queda guardada en Cloud SQL (ver la 1.5).
