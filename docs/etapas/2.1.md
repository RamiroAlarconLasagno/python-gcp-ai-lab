# Etapa 2.1: PostgreSQL local, SQLAlchemy async y Alembic

## Objetivo

Guardar cada cotización en PostgreSQL (con pgvector, que se usará en la 3.3) y poder leerla por id, con migraciones y tests de integración contra una base real.

**Terminado cuando:** el historial sobrevive al reinicio.

**Estado:** la base, las migraciones, la persistencia y los tests funcionan; la API dentro de compose falta verificarla porque su imagen no se puede construir (ver la 1.3).

## Pasos hechos

1. Dependencias: `pydantic-settings` 2.16.3, `sqlalchemy[asyncio]` 2.1.9, `asyncpg` 0.32.0 y `alembic` 1.20.1.
2. `app/config.py`: `Settings` con pydantic-settings. Lee `DATABASE_URL` del entorno o de `.env`, y las variables de entorno tienen prioridad.
3. `docker-compose.yml`:
   - Servicio `db`: `pgvector/pgvector:0.8.7-pg17`, con volumen `pgdata` y healthcheck `pg_isready`.
   - Servicio `api`: se construye desde el Dockerfile, espera a que la base esté sana, corre `alembic upgrade head` y después uvicorn. Se publica en el puerto 8000 del host.
4. `app/db.py`:
   - Modelo `QuoteRecord` y funciones `save_quote` y `get_quote`, sin patrón Repository.
   - El engine se crea la primera vez que se usa y tiene `pool_pre_ping`.
   - La cotización vence 48 horas después de crearse.
5. Alembic con la plantilla async. `migrations/env.py` toma la URL de la configuración y los metadatos de `app/db.py`. La migración `0001` crea la extensión `vector` y la tabla `quotes`, con los montos en `NUMERIC(12,2)`.
6. `app/main.py`:
   - `POST /quotes` guarda la cotización y devuelve `id`, `created_at`, `expires_at`, lo pedido y el desglose.
   - `GET /quotes/{id}` devuelve la cotización guardada, o 404 con `detail = [{"loc": ["path", "quote_id"], "msg", "type": "not_found"}]`.
7. Tests: `tests/test_api.py` pasa a ser de integración (`@pytest.mark.integration`, excluida por defecto) y suma dos casos: guardar y leer, e id inexistente → 404.

## Comandos usados

| Comando | Para qué |
|---|---|
| `docker compose up -d --wait db` | Levantar solo la base en segundo plano y esperar a que su healthcheck dé "healthy". |
| `uv run alembic upgrade head` | Aplicar todas las migraciones pendientes. |
| `uv run alembic check` | Confirmar que el modelo de `app/db.py` y la base coinciden (no falta ninguna migración). |
| `docker compose exec -T db psql -U quotes -d quotes -c "\d quotes"` | Ver la estructura de la tabla dentro del contenedor. |
| `docker compose restart db` | Reiniciar el contenedor de la base. |
| `uv run pytest -m integration` / `uv run pytest -m ""` | Solo los tests de integración / todos los tests. |
| `curl.exe` | En PowerShell; `curl` a secas es un alias de `Invoke-WebRequest`. |

## Problemas y solución

| Problema | Solución |
|---|---|
| Después de `docker compose restart db`, el primer `GET` devolvía **500**: el pool tenía una conexión que PostgreSQL ya había cerrado. Un reintento sí funcionaba. | `create_async_engine(..., pool_pre_ping=True)`: prueba la conexión antes de usarla y la reemplaza si está muerta. Verificado: el primer GET después del reinicio devuelve 200. |
| Cada test async corre en su propio event loop, y las conexiones de asyncpg quedan atadas al loop donde se abrieron. | El fixture `client` cierra el pool (`get_engine().dispose()`) al terminar cada test. |
| En el entorno de Claude, `SSLKEYLOGFILE` está definida, y con ella el OpenSSL de Python en Windows se cae (`OPENSSL_Applink`) cuando asyncpg o Alembic negocian SSL. | Claude la quita solo en sus comandos (`unset SSLKEYLOGFILE`). No afecta al proyecto. |
| `docker compose up --build` no puede construir la API (TLS de Avast dentro del contenedor). | Pendiente; ver la 1.3. |
