# ND-002: Cloud SQL for PostgreSQL as the cloud database

- **Status:** proposed
- **Date:** 2026-11-24
- **Authoring:** AI-assisted draft, to be reviewed by Ramiro.

## Context

The quote service already runs on PostgreSQL locally (docker compose, pgvector image). Quotes need durable storage in the cloud. The future RAG assistant needs vector search over a small set of fictional policy documents. This is a portfolio lab: the database lives for a short window (2026-11-25 to 2026-11-30) and is then retired.

## Decision

Use **Cloud SQL for PostgreSQL 17**, Enterprise edition, with the smallest tier:
- `db-f1-micro` (shared core), zonal.
- 10 GB SSD.
- No automated backups and no deletion protection.
- Public IP with no authorized networks. Cloud Run reaches it only through the built-in Cloud SQL connection, which is IAM-checked.

The instance name has a random suffix, because a deleted Cloud SQL name cannot be reused for a while.

## Alternatives considered

| Option | Why not (for this lab) |
|---|---|
| **AlloyDB for PostgreSQL** | It is PostgreSQL-compatible with strong vector search, but its smallest cluster is far more expensive than a shared-core Cloud SQL instance. It also needs private networking (a VPC and Private Service Access), which adds infrastructure the lab does not otherwise need. Its advantages (analytics, scale, performance) do not matter for a few hundred rows. |
| **Firestore** | Serverless and nearly free when idle, but it is a document store. The code, the migrations and the local stack are relational (SQLAlchemy, Alembic, `NUMERIC(12,2)` money), and the requirement is the *same* logic locally and in the cloud. It would also mean a second vector store instead of pgvector. |
| **Keep only local PostgreSQL** | Does not demonstrate a managed cloud database, which is one of the lab's goals. |

## Consequences

- **Same code in both environments.** The app builds its URL from parts when `DATABASE_URL` is absent (a Unix socket under `/cloudsql/`). pgvector is available: migration `0001` creates the `vector` extension on Cloud SQL without changes.
- **Cost.** It bills while it exists, even with no traffic. Prices are for us-central1, Enterprise edition, from the official Cloud SQL pricing page as read by Ramiro on 2026-11-23:

  | Item | Price | Per day |
  |---|---|---|
  | `db-f1-micro` | US$0.0105/h | US$0.252 |
  | 10 GiB SSD | US$0.000232877/GiB-h | US$0.056 |
  | Public IPv4 | US$0.01/h | US$0.240 |
  | **Total** | US$0.0228/h | **≈ US$0.55** (≈ US$3.84 per week; ≈ US$3.30 for the 6-day window) |

- **Not production-grade.** A shared core has no SLA, a zonal instance has no failover, and with no backups there is no point-in-time recovery. This is acceptable for a short-lived lab.
- **Secret handling.** The password is generated by Terraform and stored in Secret Manager. It also sits in the Terraform state, which is in a private, versioned bucket (see ND-003).

## Retirement

Run `terraform -chdir=infra destroy` in block B6. Then check with `scripts/inventario.sh` that no instance and no backup remain. The full ordered steps are in [docs/costos-y-retiro.md](../costos-y-retiro.md).
